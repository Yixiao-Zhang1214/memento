# Memento 最终馆员评语设计

日期：2026-07-29

## 1. 背景

当前馆员评语虽然已经拥有十二条内部人物参考路线，但生成效果仍容易变成
“安全的总结句”：

- 人物参考主要以抽象风格形容词进入提示词，没有转化为明确的观察方法；
- 服务端只校验字段、长度和一句话，没有校验评语是否复述正文、是否包含新观察；
- 在线模型不可用时，本地降级按手机、花、小狗等大类返回固定句子；
- 多轮补充内容后，固定评语不会真正吸收最后确定的正文与事实；
- 编辑中的每一版草稿都展示评语，削弱了馆员作为“最后盖章者”的产品角色。

本次改造把馆员评语从成稿附属字段改成最终收藏时才生成的独立编辑结果，并将
内部人物参考从“语气标签”升级为可执行的观察动作。

## 2. 目标

1. 馆员评语只在用户最终确认收藏时生成并展示。
2. 评语保持一句话，包含标点在内不超过 25 个汉字。
3. 不展示内部参考人物姓名，但不同内容应明显体现不同的观察方式。
4. 评语必须基于最终用户证据，对正文提出一个未被直接说出的具体观察。
5. 在线模型失败时仍能生成与证据、人设路线和观察动作一致的本地评语。
6. 不在每次成稿或风格调整时增加模型调用；只在最终收藏时增加一次短请求。

## 3. 非目标

- 不允许用户手动选择馆员人物或情绪路线。
- 不展示候选评语、人物姓名、生成评分或内部推理。
- 不让正文风格选择决定馆员路线。
- 不把馆员评语扩展成一段文章、建议、安慰或人生总结。
- 不进行卡片渲染、云端保存或正式小程序开发。

## 4. 已确认的产品原则

- 馆员人物由系统根据最终全部 E1 证据判断。
- 用户不知道具体参考人物，但应感到不同内容下的馆员“换了一个脑子”。
- 多轮补充可以改变最终记忆重心，因此最终路线必须使用全部最新证据重新选择。
- 馆员评语严格只有一句，长度为 8–25 个汉字，标点计入长度。
- 普通、轻松或荒诞内容允许轻微主观判断和干幽默。
- 悲伤、死亡、创伤、关系边界和用户明确收敛的内容禁止幽默。
- 趣味来自新观察、事实反差和态度，不来自堆砌修辞或增加篇幅。

## 5. 用户流程

### 5.1 编辑阶段

首次成稿、多轮补充和风格调整阶段：

- 生成标题、来源、摘要和正文；
- 不生成 `curator_note`；
- 不返回 `curator_profile`；
- 草稿页面不展示馆员区域；
- 用户仍可继续补充、继续提问、调整风格或选择“就这样收藏”。

### 5.2 最终收藏

用户点击“就这样收藏”：

1. 前端保留最终正文及全部对话历史；
2. 页面进入短暂加载态：`馆员正在写下最后一句`；
3. 前端调用 `finalize_memory`；
4. 服务端选择人物路线与观察动作；
5. 生成、校验并确定一句馆员评语；
6. 服务端把评语合并进最终文本结果；
7. 最终收藏页第一次展示馆员评语。

若在线模型失败或所有候选不合格，服务端立即使用动态本地馆员生成评语。失败
不阻断收藏，也不要求用户重试。

## 6. 系统结构

馆员系统拆分为五个职责单一的单元。

### 6.1 最终证据汇总器

输入：

- 全部 `conversation_history` 中 `role: user` 的 E1；
- 已复用的视觉 E2；
- 用户最终选定的标题、来源、摘要和正文；
- 正文风格作为 E4，仅用于避免语言冲突，不参与个人情绪事实判断。

职责：

- 保留每条证据来源；
- 使用最新用户纠正覆盖旧解释；
- 禁止把 AI 问题、模型草稿或馆员候选反向当作事实。

### 6.2 人物路线器

只根据最终 E1 选择一条主要路线。图片气氛不能支持悲伤、浪漫或怀旧等个人路线。
当信息稀少或含义不明确时使用 `neutral_sparse`。

中间草稿不生成或公开馆员路线。最终收藏时基于所有最新证据作一次最终判断，
因此用户新增的重要事实可以自然改变路线。

### 6.3 观察动作选择器

人物路线确定后，必须先选择一个观察动作，再生成句子。允许的公共安全动作 ID：

- `object_role`：指出物品在事件中实际承担的工作；
- `factual_contrast`：发现两个已知事实之间的反差；
- `small_action_consequence`：观察一个回答或动作改变了什么；
- `kept_vs_gone`：区分已经消失的事物与真正留下的部分；
- `material_time`：通过容量、磨损、搬迁等物质变化观察时间；
- `unsaid_tension`：用已知动作承载没有直接说出的关系张力；
- `shared_complicity`：抓住朋友之间共同知道的笑点或默契；
- `ordinary_absence`：让一个普通事实承担缺席，不提供安慰；
- `limit_and_continuance`：观察限制与继续生活之间的关系；
- `exact_object_observation`：信息不足时只作准确、低解释度的物品观察。

每条评语只能使用一个主要观察动作，禁止混合多个人物形成风格拼贴。

### 6.4 候选生成器

最终收藏的正常成功路径只发起一次短模型请求。上游内部结果包含最多三个候选：

```json
{
  "emotion_route": "nostalgia_change",
  "candidates": [
    {
      "text": "64G装不下后来，倒装得下六年。",
      "lens_id": "factual_contrast",
      "evidence_ids": ["E1-01", "E1-02"]
    }
  ]
}
```

候选按模型推荐顺序排列。该结构只在服务端使用；公共响应不返回未选候选。

模型必须：

- 使用选中路线允许的观察动作；
- 每个候选只表达一个观察；
- 使用至少一个具体证据；
- 不复述正文结论；
- 不暴露人物姓名或模仿声明；
- 不新增事件、关系、情绪、时间或他人心理。

### 6.5 质量闸门

服务端从前往后选择第一条全部通过的候选。每条候选必须：

1. 长度为 8–25 个 Unicode 字符，标点计入；
2. 只有一个句子结束标记；
3. `lens_id` 属于允许动作；
4. `evidence_ids` 至少包含一个有效证据；
5. 不包含内部人物姓名、路线名称或模仿声明；
6. 不包含通用套话；
7. 不是正文原句、子串或高相似改写；
8. 不包含用户未提供的具体时间、人物、关系、动作或心理结论；
9. 路线为悲伤、失去、创伤或用户边界收敛时不包含幽默或调侃；
10. 使用的观察动作与人物路线兼容。

没有候选通过时，复用现有修复机制请求模型完整重写一次。修复后仍失败，进入
动态本地馆员。

## 7. 人物路线与观察动作

人物姓名仅作为内部校准参考，任何公共输出都不得包含姓名。

| 路线 | 内部参考 | 主要观察动作 | 生成重点 | 禁止 |
|---|---|---|---|---|
| `tender_daily` | 李娟 | `object_role`, `small_action_consequence` | 日常动作里的自然温度 | 空泛甜蜜、直接宣布幸福 |
| `first_heartbeat` | 岩井俊二 | `small_action_consequence`, `object_role` | 一句话或小动作怎样改变关系 | 虚构天气、永远承诺、梦幻滤镜 |
| `intimate_tension` | 张爱玲 | `factual_contrast`, `unsaid_tension` | 已知行动里的精准反差 | 给关系下结论、尖刻审判 |
| `family_old_days` | 汪曾祺 | `object_role`, `material_time` | 食物、用法和家庭动作 | 神圣化家庭、虚构习俗 |
| `friendship_complicity` | 三毛 | `shared_complicity`, `small_action_consequence` | 共同笑点、行动与默契 | 宣布一生友情、把友情爱情化 |
| `bright_delight` | 丰子恺 | `factual_contrast`, `small_action_consequence` | 小尺度快乐与轻盈观察 | 幼稚化成人、过多感叹 |
| `absurd_self_mockery` | 王小波 | `factual_contrast`, `object_role` | 荒谬逻辑与克制判断 | 段子腔、嘲笑痛苦或用户 |
| `nostalgia_change` | 贾樟柯 | `material_time`, `kept_vs_gone` | 物质变化如何暴露时间 | 虚构时代背景、宏大历史 |
| `regret_parting` | 白先勇 | `kept_vs_gone`, `unsaid_tension` | 残留物与没有完成的连接 | 华丽悼词、替他人声明感受 |
| `grief_loss` | 余华 | `ordinary_absence`, `kept_vs_gone` | 用普通事实承受不可逆缺席 | 安慰、疗愈、成长、笑话 |
| `endurance_afterward` | 史铁生 | `limit_and_continuance`, `object_role` | 限制与继续之间的具体事实 | 励志口号、英雄化、宣布痊愈 |
| `neutral_sparse` | 阿城 | `exact_object_observation`, `object_role` | 准确名词和动作，低解释度 | 猜测情绪、装饰性诗意 |

示例只用于展示动作，不要求模型复现：

- 旧手机：`64G装不下后来，倒装得下六年。`
- 告白的花：`一个“好”字，让花有了后半生。`
- 父亲的手表：`人已经走了，手表还替他占着位置。`
- 丑但用了三年：`审美输得彻底，三年就是证据。`

## 8. 动态本地馆员

本地降级不再按物品大类返回一条固定评语，而是复用相同流程：

1. 从 E1 关键词、事件和关系选择安全路线；
2. 从该路线允许的动作中选择一个；
3. 从证据中提取短锚点，例如用户原话、数字、动作、物品或结果；
4. 使用路线专属句式骨架生成 2–3 条候选；
5. 经过与在线候选相同的质量闸门；
6. 选出第一条有效候选。

本地生成不得把复杂含义压缩成未经支持的判断。证据不足时退回
`neutral_sparse`，宁可准确而朴素，也不虚构“有趣”。

若极端情况下本地候选仍全部失败，使用最后安全句：

`馆员只留下了你确实说过的部分。`

该句只作为不可达保护，不应成为正常分类结果。

## 9. API 契约

继续使用契约版本 `1.1`，增加 `finalize_memory` 模式。

### 9.1 编辑阶段输出

`compose_memory` 和 `rewrite_text` 的未定稿阶段：

```json
{
  "status": "needs_user_input",
  "mode": "compose_memory",
  "revision_state": "awaiting_direction",
  "curator_note": null,
  "curator_profile": null
}
```

校验器只在 `revision_state: "finalized"` 时要求馆员字段存在。

### 9.2 最终收藏输入

```json
{
  "contract_version": "1.1",
  "mode": "finalize_memory",
  "conversation_history": [],
  "visual_evidence": [],
  "current_draft": {
    "title": "",
    "source_line": "",
    "summary": "",
    "story_text": ""
  }
}
```

### 9.3 最终收藏输出

```json
{
  "contract_version": "1.1",
  "status": "complete",
  "mode": "finalize_memory",
  "revision_state": "finalized",
  "title": "",
  "source_line": "",
  "summary": "",
  "story_text": "",
  "curator_note": "",
  "curator_profile": {
    "emotion_route": "neutral_sparse",
    "lens_id": "exact_object_observation"
  },
  "evidence_bindings": {
    "curator_note": ["E1-01"]
  },
  "post_draft_actions": [],
  "audit": {
    "passed": true,
    "unsupported_claims": [],
    "warnings": []
  }
}
```

公共 `curator_profile` 只包含安全路线 ID 与观察动作 ID。服务端必须删除候选列表、
内部人物、生成理由和模型修复信息。

## 10. 前端变化

### 草稿页

- 删除馆员评语区域；
- 保留继续补充、再问一个问题、收藏和风格操作；
- 收藏按钮点击后不再直接跳转最终页。

### 收藏加载态

- 文案：`馆员正在写下最后一句`；
- 禁用重复点击；
- 在线超时或限流后自动进入本地生成，不显示上游错误。

### 最终页

- 展示最终标题、来源、正文和馆员评语；
- 馆员评语只在此页出现；
- 点击“记录新的记忆”清空本地会话。

## 11. 错误与恢复

- 最终请求重复提交：沿用当前前端忙碌态；同一最终草稿的结果可在会话内复用。
- 主模型限流、过载或超时：尝试现有备用模型。
- 两个模型均失败：使用动态本地馆员。
- 在线候选不合格：修复一次，仍失败则进入动态本地馆员。
- 本地候选不合格：使用最后安全句，仍完成收藏。
- 页面刷新：HTML 验证版不恢复历史，保持现有行为。
- 最终评语不合格时不得退回中间草稿，也不得要求用户自行修改。

## 12. 测试范围

### 单元测试

- 十二条路线均能选择允许的观察动作；
- 路线与禁止动作组合被拒绝；
- 8–25 字边界；
- 多句、人物姓名、路线名称和模仿声明被拒绝；
- 通用套话被拒绝；
- 与正文原句或高相似改写被拒绝；
- 无有效证据绑定的候选被拒绝；
- 悲伤路线中的幽默候选被拒绝；
- 动态本地馆员使用最终 E1，而不是固定物品分类；
- 多轮新增事实可以改变最终路线；
- `neutral_sparse` 不推断个人情绪。

### 服务测试

- 中间 `compose_memory` 不生成馆员字段；
- `rewrite_text` 不生成或修改馆员字段；
- `finalize_memory` 正常成功路径只调用一次短馆员生成；
- 在线候选有效时返回最高优先有效候选；
- 在线候选全部无效时修复一次；
- 两个模型不可用时仍完成最终收藏；
- 公共响应不包含候选、人物姓名或内部理由；
- 最终评语绑定到有效证据。

### 浏览器验收

1. 首次成稿页面没有馆员评语；
2. 多轮继续补充后仍不出现馆员评语；
3. 风格调整后仍不出现馆员评语；
4. 点击收藏出现“馆员正在写下最后一句”；
5. 最终页第一次显示评语；
6. 最终评语不超过 25 字；
7. 模型限流时无需重试即可进入最终页；
8. 新记忆不会复用上一条馆员评语。

## 13. 验收标准

1. 编辑阶段不生成、不返回、不展示馆员评语。
2. 只有 `finalize_memory` 生成馆员评语。
3. 最终评语严格为一句且不超过 25 个汉字。
4. 最终评语使用至少一条有效证据并提出正文未直接表达的观察。
5. 十二条内部人物路线继续有效，公共输出不出现人物姓名。
6. 人物路线决定观察方式，而不只是情绪词和形容词。
7. 轻松内容允许有判断或干幽默，沉重内容自动禁用幽默。
8. 多轮补充后的最终路线使用全部最新用户输入。
9. 本地降级不返回按物品类别写死的固定评语。
10. 主模型、备用模型和修复全部失败时，收藏流程仍完成。
11. 最终页正确显示正文和馆员评语。
